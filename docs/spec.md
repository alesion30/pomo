# pomo 仕様

pomo は、自分用の macOS ポモドーロアプリです。集中と休憩のタイマー、メニューバー表示、区切りで前面に出るメインウィンドウ、セッションごとのメモを持ちます。セッションの記録は、AI がそのまま読める JSONL で残します。

## 作らないもの

- キーボードショートカット
- アプリ内の統計画面
- 通知音の選択、集中モード（おやすみモード）との連動
- 端末間の同期
- 設定画面
- 一時停止
- 他アプリからのデータ移行
- App Store、Homebrew での配布

## 技術構成

| 項目 | 選択 |
|---|---|
| アプリ基盤 | Tauri v2 |
| UI | React、TypeScript |
| パッケージマネージャ | pnpm |
| 対象 | macOS、Apple Silicon（aarch64） |
| バンドル ID | `dev.alesion30.pomo` |

時間の設定値はコード内の定数にします。

| 定数 | 値 |
|---|---|
| 集中 | 25 分 |
| 短い休憩 | 5 分 |
| 長い休憩 | 20 分 |
| 長い休憩までの集中回数 | 4 回 |
| 予定時間の増減幅 | 5 分 |
| 予定時間の下限 | 5 分 |
| 連続とみなす間隔 | 60 分 |

開発時のライブ E2E を短縮するため、`POMO_TIME_SCALE` で時間を縮尺できます。未設定なら `1`、デバッグビルドでのみ有効です。時間縮尺を使った E2E が不要になったら、この設定を削除します。

## タイマー

フェーズは「待機」「集中」「短い休憩」「長い休憩」の 4 つです。

- 集中が予定時間に到達しても止まりません。超過分をオーバータイムとして数え続けます。休憩も同じです。
- 進行中のフェーズは、開始時刻と予定時間だけを持ちます。残り時間とオーバータイムは現在時刻から計算します。そのため、スリープ中も時間は進みます。
- ±5 分の操作は予定時間を増減します。予定時間が経過時間を下回ったら、その時点からオーバータイム表示になります。予定時間は 5 分未満になりません。ただし残りが 5 分未満で −5 分を選ぶと、予定時間を経過時間にそろえ、すぐオーバータイムにします。この集中は予定時間に到達したものとして `completed` に数えます。
- 予定時間に到達した集中を `completed` として数えます。4 回目の `completed` の後の休憩は長い休憩です。カウントは、長い休憩を終えたときと、直前のフェーズの終了から 60 分以上空いて集中を始めたときに 0 に戻ります。休憩をスキップした場合も間隔を正しく測るため、基準は休憩ではなく直前のフェーズの終了にします。
- 集中を予定時間より前に終えたら `ended_early` として記録し、待機に戻ります。この集中はカウントしません。
- 集中中に「休憩」を選ぶと、その時点で集中を記録して休憩を始めます。予定時間前なら短い休憩、完了後は通常の回数に応じた休憩です。
- 集中中の「休憩」と「終了」は、予定時間前なら確認してから実行します。予定時間前の集中は回数に数えないためです。
- 集中中に「破棄」を選び、確認すると集中を記録せず待機に戻ります。タイトルとカテゴリは残り、振り返りは消えます。
- 集中終了時のウィンドウでは、休憩を始めるか、休憩をスキップするかを選びます。スキップすると待機に戻り、メインウィンドウは前に出す前の位置と表示の状態に戻ります。前に出す前に隠れていたら、また隠れます。
- 休憩中に「集中を開始」を選ぶと、その時点までを実際の休憩時間として記録し、すぐ次の集中を始めます。
- 休憩中に「休憩を破棄」を選び、確認すると休憩を記録せずに待機に戻ります。連続の回数と直前のフェーズの終了時刻は変えません。
- 進行中の状態はファイルに保存し、アプリを再起動しても再開します。

## 画面

### メニューバー

- Dock にアイコンを表示し、通常起動ではメインウィンドウを開きます。
- 集中中はタイトルと残り時間を表示します。例は `PRレビュー対応 - 18:32` です。タイトルは全角 12 文字程度で `…` に切り詰めます。タイトルが空なら時間だけを表示します。
- オーバータイム中は `PRレビュー対応 - +03:12` のように表示します。
- 休憩中は休憩とわかる表示にします。例は `☕ 03:10` です。
- クリックするとメインウィンドウを開きます。

### メインウィンドウ

- 大きさは 680×400 で固定です。どの画面もスクロールせずに収まります。
- 他のアプリのウィンドウより上に出し続けます（フローティングの階層）。他のアプリの全画面表示のスペースには出しません。隠したいときはウィンドウを閉じます。
- 外観はダークだけです。macOS の外観設定がライトでも同じ見た目で、タイトルバーもダークにします。
- 左に時間、右に内容と操作を置きます。
  - 左には現在のフェーズ、リング状のダイヤル、±5 分を置きます。ダイヤルは残り時間を中央の数字と点いた弧の長さで示します。待機中は `--:--` で、弧は消えています。
  - 右にはタイトル、カテゴリ、振り返りの入力と、開始、休憩、終了、破棄のボタンを置きます。タイトルは全角 40 文字でも折り返して全文が見えます。カテゴリは自由入力で、過去の入力値から候補を出します。
- フェーズは色で区別します。待機は無彩色、集中はトマトの赤、休憩は葉の緑です。進行中は背景に淡く色が差し、予定時間に到達すると区切り画面として背景全体がその色になります。
- 待機中は開始、集中中は休憩・終了・破棄と ±5 分、休憩中は集中を開始・休憩を破棄と ±5 分を操作できます。休憩中は振り返りの欄を出さず、次の集中のタイトルとカテゴリを入れます。
- 集中と休憩の破棄、予定時間前の休憩と終了、集中中または休憩中の ⌘Q は、ウィンドウの中央に確認を重ねて出します。
- 更新があるときは右下に「更新あり」を表示します。適用できるのは待機中だけです。
- 色は `src/app.css` の先頭にカスタムプロパティとしてまとめます。ウィンドウの地の色だけは、表示した瞬間に白く見えないよう `src-tauri/tauri.conf.json` の `backgroundColor` と `index.html` にも同じ値を書きます。フォントはシステムフォントだけを使います。

### 区切り画面

- 集中の予定時間に到達したときと、休憩の予定時間に到達したときに出します。±5 分の操作で予定時間を過ぎた場合は、前面化と通知をせず、ウィンドウの中身だけを区切りの画面にします。
- 区切り画面は、メインウィンドウを前面に出して表示します。区切りの操作を終えるか閉じると、前面に出す前の位置と表示の状態に戻します。前面に出す前に別のスペースにあって見えていなかった場合は、閉じた状態に戻し、それまでの作業（全画面アプリなど）に戻ります。
- 全スペースに出し、他アプリの全画面表示の上にも重ねます。Dock に出るアプリのウィンドウは他アプリの全画面表示に重ねられないため、区切り画面を出している間は Dock のアイコンを消します。
- 集中終了時のウィンドウでは、振り返りを確定し、休憩開始かスキップを選びます。±5 分も操作できます。ダイヤルには超過時間を出し、右には終えた集中のタイトルとカテゴリを出します。
- 休憩終了時のウィンドウでは、次のタイトルとカテゴリを入れて集中を始めるか、休憩を破棄します。ダイヤルには休憩の超過時間を出します。

### 通知

区切りでメインウィンドウを前に出すのと同時に、システム音付きの通知を出します。

## セッションログ

- 保存先は `~/.local/share/pomo/sessions.jsonl` です。`XDG_DATA_HOME` が設定されていれば、`$XDG_DATA_HOME/pomo/` を使います。
- フェーズが終わるたびに 1 行追記します。既存の行は書き換えません。
- 確定後のメモを直したいときは、ファイルを直接編集します。

1 行のフィールドは次のとおりです。

| フィールド | 型 | 内容 |
|---|---|---|
| `id` | string | UUID |
| `kind` | `"focus"` \| `"short_break"` \| `"long_break"` | フェーズの種類 |
| `title` | string \| null | タイトル。休憩では null |
| `category` | string \| null | カテゴリ。休憩では null |
| `notes` | string \| null | 振り返り。休憩では null |
| `started_at` | string | 開始時刻。タイムゾーン付きの ISO 8601 |
| `ended_at` | string | 終了時刻。タイムゾーン付きの ISO 8601 |
| `planned_sec` | number | 終了時点の予定時間（秒） |
| `actual_sec` | number | 実際の経過時間（秒） |
| `outcome` | `"completed"` \| `"ended_early"` | 予定時間に到達したかどうか |

例:

```json
{"id":"3f1c…","kind":"focus","title":"PRレビュー","category":"レビュー","notes":"指摘2件を返した","started_at":"2026-11-11T17:48:59+09:00","ended_at":"2026-11-11T18:24:07+09:00","planned_sec":1800,"actual_sec":2108,"outcome":"completed"}
```

## 起動と更新

- ログイン時に自動で起動し、ウィンドウは隠れたままです。
- 赤ボタンや ⌘W で閉じてもタイマーは動き、Dock アイコンかメニューバーをクリックすると同じ位置に開き直します。
- ⌘Q は集中中または休憩中に確認を出します。待機中はすぐ終了します。Dock メニューの終了と AppleScript の quit は確認を経由しません。
- 起動時と 6 時間おきに、GitHub Releases の更新情報を確認します。
- 更新はメインウィンドウのボタンを押したときにだけ適用します。集中中と休憩中は押せません。

## 配布

- `v*` タグを push すると、GitHub Actions が dmg をビルドして GitHub Releases に置きます。
- コード署名は ad-hoc です。同じ場所の .app を作り直したビルドに置き換えても、通知の許可は残ることを確かめています（`docs/plan.md` の Appendix A の A3）。
- 初回のインストールでは、Gatekeeper の解除が必要です。手順は README に書きます。

## 開発の流れと秘密情報の防止

- リポジトリは public です。
- 変更は機能ごとのブランチと PR で入れます。main は保護し、CI が通ったものだけをマージします。
- 秘密情報は次の 3 層で防ぎます。
  1. lefthook の pre-commit で gitleaks を実行する。
  2. CI で全履歴に対して gitleaks を実行する。
  3. GitHub の Secret scanning と Push protection を有効にする。
- 自動更新の署名鍵は GitHub Actions の secrets にだけ置きます。
- テストのデータはダミーにします。セッションログはリポジトリの外に書きます。
