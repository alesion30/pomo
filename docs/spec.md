# pomo 仕様

pomo は、自分用の macOS ポモドーロアプリです。集中と休憩のタイマー、メニューバー表示、区切りで前面に出るウィンドウ、セッションごとのメモを持ちます。セッションの記録は、AI がそのまま読める JSONL で残します。

## 作らないもの

- キーボードショートカット
- アプリ内の統計画面
- 通知音の選択、集中モード（おやすみモード）との連動
- 端末間の同期
- 設定画面
- 一時停止
- 他アプリからのデータ移行
- App Store、Homebrew での配布

## 技術構成

| 項目 | 選択 |
|---|---|
| アプリ基盤 | Tauri v2 |
| UI | React、TypeScript |
| パッケージマネージャ | pnpm |
| 対象 | macOS、Apple Silicon（aarch64） |
| バンドル ID | `dev.alesion30.pomo` |

時間の設定値はコード内の定数にします。

| 定数 | 値 |
|---|---|
| 集中 | 25 分 |
| 短い休憩 | 5 分 |
| 長い休憩 | 20 分 |
| 長い休憩までの集中回数 | 4 回 |
| 予定時間の増減幅 | 5 分 |
| 予定時間の下限 | 5 分 |
| 連続とみなす間隔 | 60 分 |

## タイマー

フェーズは「待機」「集中」「短い休憩」「長い休憩」の 4 つです。

- 集中が予定時間に到達しても止まりません。超過分をオーバータイムとして数え続けます。休憩も同じです。
- 進行中のフェーズは、開始時刻と予定時間だけを持ちます。残り時間とオーバータイムは現在時刻から計算します。そのため、スリープ中も時間は進みます。
- ±5 分の操作は予定時間を増減します。予定時間が経過時間を下回ったら、その時点からオーバータイム表示になります。予定時間は 5 分未満になりません。
- 予定時間に到達した集中を `completed` として数えます。4 回目の `completed` の後の休憩は長い休憩です。カウントは、長い休憩を終えたときと、前の休憩の終了から 60 分以上空いて集中を始めたときに 0 に戻ります。
- 集中を予定時間より前に終えたら `ended_early` として記録し、待機に戻ります。この集中はカウントしません。
- 集中終了時のウィンドウでは、休憩を始めるか、休憩をスキップして待機に戻るかを選びます。
- 休憩はいつでも終えられます。終えた時点までを実際の休憩時間として記録します。
- 進行中の状態はファイルに保存し、アプリを再起動しても再開します。

## 画面

### メニューバー

- Dock には出さず、メニューバーにだけ常駐します。
- 集中中は残り時間とタイトルを表示します。例は `18:32 PRレビュー対応` です。タイトルは全角 12 文字程度で `…` に切り詰めます。
- オーバータイム中は `+03:12` のように表示します。
- 休憩中は休憩とわかる表示にします。例は `☕ 03:10` です。
- クリックするとポップオーバーを開きます。

### ポップオーバー

- 現在のフェーズと時間を表示します。
- タイトル、カテゴリ、振り返りを入力できます。カテゴリは自由入力で、過去の入力値から補完します。
- 開始、終了、±5 分を操作できます。
- 更新があるときは「更新あり」を表示します。適用できるのは待機中だけです。

### 最前面ウィンドウ

- 集中の予定時間に到達したときと、休憩の予定時間に到達したときに出します。
- 全スペースに出し、他アプリの全画面表示の上にも重ねます。
- 集中終了時のウィンドウでは、振り返りを確定し、休憩開始かスキップを選びます。±5 分も操作できます。
- 休憩終了時のウィンドウでは、次のタイトルとカテゴリを入れて集中を始めます。

### 通知

最前面ウィンドウを出すのと同時に、システム音付きの通知を出します。

## セッションログ

- 保存先は `~/.local/share/pomo/sessions.jsonl` です。`XDG_DATA_HOME` が設定されていれば、`$XDG_DATA_HOME/pomo/` を使います。
- フェーズが終わるたびに 1 行追記します。既存の行は書き換えません。
- 確定後のメモを直したいときは、ファイルを直接編集します。

1 行のフィールドは次のとおりです。

| フィールド | 型 | 内容 |
|---|---|---|
| `id` | string | UUID |
| `kind` | `"focus"` \| `"short_break"` \| `"long_break"` | フェーズの種類 |
| `title` | string \| null | タイトル。休憩では null |
| `category` | string \| null | カテゴリ。休憩では null |
| `notes` | string \| null | 振り返り。休憩では null |
| `started_at` | string | 開始時刻。タイムゾーン付きの ISO 8601 |
| `ended_at` | string | 終了時刻。タイムゾーン付きの ISO 8601 |
| `planned_sec` | number | 終了時点の予定時間（秒） |
| `actual_sec` | number | 実際の経過時間（秒） |
| `outcome` | `"completed"` \| `"ended_early"` | 予定時間に到達したかどうか |

例:

```json
{"id":"3f1c…","kind":"focus","title":"PRレビュー","category":"レビュー","notes":"指摘2件を返した","started_at":"2026-11-11T17:48:59+09:00","ended_at":"2026-11-11T18:24:07+09:00","planned_sec":1800,"actual_sec":2108,"outcome":"completed"}
```

## 起動と更新

- ログイン時に自動で起動します。
- 起動時と 6 時間おきに、GitHub Releases の更新情報を確認します。
- 更新はポップオーバーのボタンを押したときにだけ適用します。集中中と休憩中は押せません。

## 配布

- `v*` タグを push すると、GitHub Actions が dmg をビルドして GitHub Releases に置きます。
- コード署名は ad-hoc です。更新のたびに通知の許可が外れる場合は、自己署名の証明書で署名を固定します。
- 初回のインストールでは、Gatekeeper の解除が必要です。手順は README に書きます。

## 開発の流れと秘密情報の防止

- リポジトリは public です。
- 変更は機能ごとのブランチと PR で入れます。main は保護し、CI が通ったものだけをマージします。
- 秘密情報は次の 3 層で防ぎます。
  1. lefthook の pre-commit で gitleaks を実行する。
  2. CI で全履歴に対して gitleaks を実行する。
  3. GitHub の Secret scanning と Push protection を有効にする。
- 自動更新の署名鍵は GitHub Actions の secrets にだけ置きます。
- テストのデータはダミーにします。セッションログはリポジトリの外に書きます。
