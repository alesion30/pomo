# pomo 仕様

pomo は、自分用の macOS ポモドーロアプリです。集中と休憩のタイマー、メニューバー表示、区切りで前面に出るメインウィンドウ、セッションごとのメモを持ちます。セッションの記録は、AI がそのまま読める JSONL で残します。

## 作らないもの

- キーボードショートカット
- アプリ内の統計画面（履歴画面に出す集計は、その日の合計だけです）
- 通知音の選択、集中モード（おやすみモード）との連動
- 端末間の同期
- 一時停止
- 他アプリからのデータ移行
- App Store、Homebrew での配布

## 技術構成

| 項目 | 選択 |
|---|---|
| アプリ基盤 | Tauri v2 |
| UI | React、TypeScript |
| パッケージマネージャ | pnpm |
| 対象 | macOS、Apple Silicon（aarch64） |
| バンドル ID | `dev.alesion30.pomo` |

時間の設定値はコード内の定数にします。カテゴリの一覧だけを設定ファイルに置きます（「設定ファイル」の節）。

| 定数 | 値 |
|---|---|
| 集中 | 25 分 |
| 短い休憩 | 5 分 |
| 長い休憩 | 20 分 |
| 長い休憩までの集中回数 | 4 回 |
| 予定時間の増減幅 | 5 分 |
| 予定時間の下限 | 5 分 |
| 連続とみなす間隔 | 60 分 |

開発時のライブ E2E を短縮するため、`POMO_TIME_SCALE` で時間を縮尺できます。未設定なら `1`、デバッグビルドでのみ有効です。時間縮尺を使った E2E が不要になったら、この設定を削除します。

## タイマー

フェーズは「待機」「集中」「短い休憩」「長い休憩」の 4 つです。

- 集中が予定時間に到達しても止まりません。超過分をオーバータイムとして数え続けます。休憩も同じです。
- 進行中のフェーズは、開始時刻と予定時間だけを持ちます。残り時間とオーバータイムは現在時刻から計算します。そのため、スリープ中も時間は進みます。
- ±5 分の操作は予定時間を増減します。予定時間が経過時間を下回ったら、その時点からオーバータイム表示になります。予定時間は 5 分未満になりません。ただし残りが 5 分未満で −5 分を選ぶと、予定時間を経過時間にそろえ、すぐオーバータイムにします。この集中は予定時間に到達したものとして `completed` に数えます。
- 集中中と休憩中は、開始時刻と予定時間を編集できます。開始時刻は今より後にできず、予定時間は 1 分以上です。今より後の時刻を入れたときは、12 時間より先なら前日の時刻として扱い、それ以外は保存できません。編集の結果、予定の終了が今より前になったら、−5 分と同じくすぐオーバータイムにし、ウィンドウを前に出したり通知したりはしません。記録の開始時刻と実際の時間は、編集した開始時刻から数えます。
- 予定時間に到達した集中を `completed` として数えます。4 回目の `completed` の後の休憩は長い休憩です。カウントは、長い休憩を終えたときと、直前のフェーズの終了から 60 分以上空いて集中を始めたときに 0 に戻ります。休憩をスキップした場合も間隔を正しく測るため、基準は休憩ではなく直前のフェーズの終了にします。
- 集中を予定時間より前に終えたら `ended_early` として記録し、待機に戻ります。この集中はカウントしません。
- 集中中に「休憩」を選ぶと、その時点で集中を記録して休憩を始めます。予定時間前なら短い休憩、完了後は通常の回数に応じた休憩です。
- 集中中の「休憩」と「終了」は、振り返りを書く画面を出し、確定してから実行します。キャンセルすると集中を続け、書いた振り返りは残ります。予定時間前なら、この集中を回数に数えないことを同じ画面で伝えます。
- 集中を記録したあとも、タイトルとカテゴリは入力欄に残り、次の集中の初期値になります。振り返りは消えます。
- 集中中に「破棄」を選び、確認すると集中を記録せず待機に戻ります。タイトルとカテゴリは残り、振り返りは消えます。
- 集中終了時のウィンドウでは、休憩を始めるか、休憩をスキップするかを選びます。スキップすると待機に戻り、メインウィンドウは前に出す前の位置と表示の状態に戻ります。前に出す前に隠れていたら、また隠れます。
- 休憩中に「集中を開始」を選ぶと、その時点までを実際の休憩時間として記録し、すぐ次の集中を始めます。
- 休憩中に「休憩を破棄」を選び、確認すると休憩を記録せずに待機に戻ります。連続の回数と直前のフェーズの終了時刻は変えません。
- 進行中の状態はファイルに保存し、アプリを再起動しても再開します。

## 画面

### メニューバー

- Dock にアイコンを表示し、通常起動ではメインウィンドウを開きます。
- 集中中はタイトルと残り時間を表示します。例は `PRレビュー対応 - 18:32` です。タイトルは全角 12 文字程度で `…` に切り詰めます。タイトルが空なら時間だけを表示します。
- オーバータイム中は `PRレビュー対応 - +03:12` のように表示します。
- 休憩中は休憩とわかる表示にします。例は `☕ 03:10` です。
- クリックするとメインウィンドウを開きます。

### メインウィンドウ

- 大きさは、タイトルバーを含めて 360×544（内側は 360×512）で固定です。どの画面もスクロールせずに収まります。設定画面のカテゴリの一覧と履歴画面の記録の一覧だけは、数に上限がないので一覧の中で送ります。
- 他のアプリのウィンドウより上に出し続けます（フローティングの階層）。他のアプリの全画面表示のスペースには出しません。隠したいときはウィンドウを閉じます。
- 外観はダークだけです。macOS の外観設定がライトでも同じ見た目で、タイトルバーもダークにします。
- 上から下へ 1 列に並べます。上から、回数の点と履歴・設定を開くボタン、タイトル、カテゴリ、文字盤、時間、開始・予定の終了の時刻と ±5 分、操作のボタンです。
  - 回数の点は 4 つで、長い休憩までに終えた集中の数だけ塗ります。集中中は、今の集中を輪で示します。待機中に、直前のフェーズの終了から 60 分以上たっていれば、次の集中で数え直すので、すべて消して出します。
  - タイトルは中央に大きく置き、空のときは「何に集中しますか？」と問いかけます。全角 40 文字でも折り返して全文が見えます。カテゴリは「なし」と設定ファイルの一覧から選び、色の点を添えます。待機中、集中中、休憩中で同じ選択欄を使います。一覧にないカテゴリが進行中の集中に付いていれば、名前をそのまま出して記録にも使います。待機中と休憩中の入力欄に残っているだけなら「なし」に戻します。
  - 文字盤は 60 分で 1 周する時計の形です。残り時間を、12 時の位置から右回りに広がる扇と、その端の針で示します。残りが 60 分を超える間は 1 周を塗ったままです。待機中は、これから始める集中の長さを薄く出します。休憩中は、扇と針の代わりに輪とカップの印で出します。
  - 文字盤の下に、残り時間を数字で出します。待機中は集中の長さ（`25:00`）です。その下に開始・予定の終了の時刻（`10:47 → 11:12`、24 時間表記）を置き、両脇に ±5 分を置きます。時刻を押すと、開始時刻と予定時間（時と分）を編集する画面を重ねて出します。待機中は、今始めた場合の開始と終了の時刻を、押せない表示として出します。
- 色は 2 つの役割に分けます。待機中と集中中は、選んだカテゴリの色を文字盤、回数の点、開始のボタンに使います。カテゴリが「なし」ならトマトの赤です。休憩中は、カテゴリに関係なく葉の緑です。予定時間に到達すると、区切り画面として背景全体が色になります。集中の区切りはトマトの赤、休憩の区切りは葉の緑で、カテゴリの色には左右されません。緑のカテゴリの集中と休憩は、文字盤の形で見分けます。
- 待機中は開始、集中中は休憩・終了・破棄と ±5 分、休憩中は集中を開始・休憩を破棄と ±5 分を操作できます。主の操作は、どの状態でも下端に置きます。休憩中は、次の集中のタイトルとカテゴリを入れます。
- 振り返りの欄は、集中を閉じるときだけ出します。待機中、集中中、休憩中のタイマーの画面には置きません。集中中に「休憩」か「終了」を押すと、ウィンドウの中央に振り返りを書く画面を重ねて出します。上から、見出し（「休憩に入る」「集中を終了」）、今の集中のタイトルとカテゴリ、振り返りの欄、キャンセルと確定のボタンです。開くと振り返りの欄にカーソルが入り、⌘Enter で確定、Esc でキャンセルできます。振り返りは空のままでも確定できます。予定時間に到達した集中は、集中終了の画面で振り返りを書きます。
- 集中と休憩の破棄、集中中または休憩中の ⌘Q は、ウィンドウの中央に確認を重ねて出します。取り消せない操作（破棄、記録の削除）とアプリの終了だけ、実行のボタンを赤にします。
- 色は `src/app.css` の先頭にカスタムプロパティとしてまとめます。ウィンドウの地の色（`#17181b`）だけは、表示した瞬間に白く見えないよう `src-tauri/tauri.conf.json` の `backgroundColor` と `index.html` にも同じ値を書きます。フォントはシステムフォントだけを使います。

### 設定画面

- メインウィンドウの中で、タイマーの画面と切り替えて出します。右上の歯車、アプリのメニューの「設定…」（⌘,）から開き、✕ か Esc で閉じます。
- タイマーが進んでいる間も開けます。区切りを迎えたら、区切り画面を優先して出し、区切りを抜けると設定画面に戻ります。
- カテゴリの追加、名前の変更、削除、並べ替えができます。名前を変えても、過去の記録は書き換えません。
- カテゴリの左の丸を押すと、その行の下に 6 色（青、黄、紫、桃、緑、赤）と「自動」が並び、色を選べます。「自動」は一覧の並び順で色を決めます。名前を変えると色も付いていき、削除すると色の設定も消えます。
- 下の段に、今のバージョンと「アップデートを確認」を置きます。起動時と定期の確認、または「アップデートを確認」で更新が見つかると、その下に「更新あり」を出します。適用できるのは待機中だけで、適用に失敗したら理由を出します。更新の情報はタイマーの画面には出しません。
- 「設定ファイルを Finder で表示」で `config.json` の場所を開きます。

### 履歴画面

- メインウィンドウの中で、タイマーの画面と切り替えて出します。右上の時計のボタンから開き、✕ か Esc で閉じます。設定画面とは同時に出しません。
- タイマーが進んでいる間も開けます。区切りを迎えたら、区切り画面を優先して出し、区切りを抜けると履歴画面に戻ります。このとき、表示する日は今日に戻り、入力の途中だった追加や編集は残りません。
- 1 日分の集中の記録を、開始の新しい順に並べます。その日に始まった集中が対象で、休憩は出しません。開いたときは今日で、前の日と次の日に送れます。今日より先には送れません。
- 上には日付、その日の集中の合計時間と回数、0 時から 24 時のどこで集中したかを示す帯を置きます。帯の下に 6 時間ごとの時刻を添えます。
- 1 件には、タイトル、開始と終了の時刻（24 時間表記）、振り返り、カテゴリ、実際の時間（分）を出します。タイトルが空なら「（タイトルなし）」です。左の線と上の帯の印とカテゴリの点は、カテゴリごとの色です。設定画面で選んだ色を使います。選んでいなければ一覧の並び順で 6 色を順に使い、一覧にないカテゴリの色は名前から決めます。予定時間の前に終えた集中には「途中で終了」を添え、左の線を破線にします。
- 「＋ 追加」で、表示している日に記録を足します。時刻の初期値は、今日なら今を終了にした 25 分、過去の日ならその日の最後の記録の続き（なければ 9 時）からの 25 分です。足した記録は、実際の時間を予定時間にした `completed` の集中として残します。
- 各記録の鉛筆のボタンで、タイトル、カテゴリ、振り返り、開始と終了の時刻を編集できます。予定時間は変えず、実際の時間と `outcome` を時刻から数え直します。変えなかった時刻は秒まで元の値を保ちます。
- 時刻は表示している日の「時:分」で入れます。終了が開始より前の時刻なら翌日の時刻として扱い、「翌日」と長さを添えて示します。終了が開始と同じか、今より後なら保存できず、理由を入力の下に出します。
- 各記録のゴミ箱のボタンで削除します。必ず確認を挟みます。
- 記録の読み込み、保存、削除に失敗したら、理由を画面に出します。

### 区切り画面

- 集中の予定時間に到達したときと、休憩の予定時間に到達したときに出します。±5 分の操作で予定時間を過ぎた場合は、前面化と通知をせず、ウィンドウの中身だけを区切りの画面にします。
- 区切り画面は、メインウィンドウを前面に出して表示します。区切りの操作を終えるか閉じると、前面に出す前の位置と表示の状態に戻します。前面に出す前に別のスペースにあって見えていなかった場合は、閉じた状態に戻し、それまでの作業（全画面アプリなど）に戻ります。
- 全スペースに出し、他アプリの全画面表示の上にも重ねます。Dock に出るアプリのウィンドウは他アプリの全画面表示に重ねられないため、区切り画面を出している間は Dock のアイコンを消します。
- 背景全体を色にし、中央に見出し（「集中終了」「休憩終了」）と超過時間を大きく出します。文字盤は出しません。回数の点は、今終えた集中を数えて出します。
- 集中終了時のウィンドウでは、振り返りを確定し、休憩開始かスキップを選びます。±5 分も操作できます。見出しの下に終えた集中のタイトルとカテゴリを出し、その下の広い欄に振り返りを書きます。
- 休憩終了時のウィンドウでは、次のタイトルとカテゴリを入れて集中を始めるか、休憩を破棄します。

### 通知

区切りでメインウィンドウを前に出すのと同時に、システム音付きの通知を出します。

## 設定ファイル

- 保存先は `~/.config/pomo/config.json` です。`XDG_CONFIG_HOME` が設定されていれば、`$XDG_CONFIG_HOME/pomo/` を使います。
- 形式は `{"categories": ["開発", "レビュー"], "colors": {"開発": "sky"}}` です。`colors` はカテゴリ名から色の名前（`sky` `amber` `violet` `rose` `leaf` `tomato`）への対応で、書いていないカテゴリは自動の色です。手で編集してもかまいません。アプリが知らないキーは、設定画面から保存しても残します。
- ファイルがなければ、起動時に `{"categories": []}` で作ります。
- ウィンドウが前面に来るたびに読み直します。壊れていたら前に読めた内容を使い続け、設定画面にエラーを出します。壊れている間は、設定画面からは保存しません。

## セッションログ

- 保存先は `~/.local/share/pomo/sessions.jsonl` です。`XDG_DATA_HOME` が設定されていれば、`$XDG_DATA_HOME/pomo/` を使います。
- フェーズが終わるたびに 1 行追記します。既存の行を書き換えるのは、履歴画面で記録を追加、編集、削除したときだけです。
- 確定後のメモは、履歴画面から直します。ファイルを直接編集してもかまいません。

1 行のフィールドは次のとおりです。

| フィールド | 型 | 内容 |
|---|---|---|
| `id` | string | UUID |
| `kind` | `"focus"` \| `"short_break"` \| `"long_break"` | フェーズの種類 |
| `title` | string \| null | タイトル。休憩では null |
| `category` | string \| null | カテゴリ。休憩では null |
| `notes` | string \| null | 振り返り。休憩では null |
| `started_at` | string | 開始時刻。タイムゾーン付きの ISO 8601 |
| `ended_at` | string | 終了時刻。タイムゾーン付きの ISO 8601 |
| `planned_sec` | number | 終了時点の予定時間（秒） |
| `actual_sec` | number | 実際の経過時間（秒） |
| `outcome` | `"completed"` \| `"ended_early"` | 予定時間に到達したかどうか |

例:

```json
{"id":"3f1c…","kind":"focus","title":"PRレビュー","category":"レビュー","notes":"指摘2件を返した","started_at":"2026-11-11T17:48:59+09:00","ended_at":"2026-11-11T18:24:07+09:00","planned_sec":1800,"actual_sec":2108,"outcome":"completed"}
```

## 起動と更新

- ログイン時に自動で起動し、ウィンドウは隠れたままです。
- 赤ボタンや ⌘W で閉じてもタイマーは動き、Dock アイコンかメニューバーをクリックすると同じ位置に開き直します。
- ⌘Q は集中中または休憩中に確認を出します。待機中はすぐ終了します。Dock メニューの終了と AppleScript の quit は確認を経由しません。
- 起動時と 6 時間おきに、GitHub Releases の更新情報を確認します。
- 更新は設定画面の「更新あり」を押したときにだけ適用します。集中中と休憩中は押せません。

## 配布

- `v*` タグを push すると、GitHub Actions が dmg をビルドして GitHub Releases に置きます。
- コード署名は ad-hoc です。同じ場所の .app を作り直したビルドに置き換えても、通知の許可は残ることを確かめています（`docs/plan.md` の Appendix A の A3）。
- 初回のインストールでは、Gatekeeper の解除が必要です。手順は README に書きます。

## 開発の流れと秘密情報の防止

- リポジトリは public です。
- 変更は機能ごとのブランチと PR で入れます。main は保護し、CI が通ったものだけをマージします。
- 秘密情報は次の 3 層で防ぎます。
  1. lefthook の pre-commit で gitleaks を実行する。
  2. CI で全履歴に対して gitleaks を実行する。
  3. GitHub の Secret scanning と Push protection を有効にする。
- 自動更新の署名鍵は GitHub Actions の secrets にだけ置きます。
- テストのデータはダミーにします。セッションログはリポジトリの外に書きます。
